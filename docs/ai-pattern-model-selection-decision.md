# EasyInput AI 鼓点模型选型决策

状态：已决策，进入 MVP 接入  
日期：2026-08-30  
决策对象：文字生成六音色、单小节 16 步 Pattern  
选定方案：DeepSeek V4 Flash

## 1. 选型结论

EasyInput AI 鼓点 MVP 选择 DeepSeek API 的 `deepseek-v4-flash` 作为接入模型。请求与响应均记录别名 `deepseek-v4-flash`；实验时官方文档的映射版本登记为 `DeepSeek-V4-Flash-0731`，API 响应没有独立解析出该版本。产品首版沿用实验中的非思考模式。

这是一项面向当前产品配置的 MVP 决策，不是基础模型能力排名。DeepSeek 与智谱均通过两项实验硬门槛，并在结构、指令两项获得满分及各 6/6 `PATTERN` ACK。DeepSeek 的主要优势是完整合法 Pattern 的响应速度。智谱在单人盲听中的得分更高，因此本结论不包含 DeepSeek 音乐品味更好这一判断。

决策状态记为：

```text
mvp_model_selected_for_integration; benchmark_winner_not_established
```

## 2. 产品问题与实验范围

实验目标是选择一个能够把中文自然语言稳定转换为当前开发板可执行 Pattern 的模型。当前执行合同包括：

- 4/4 拍、单小节 16 步；
- Kick、Snare、Closed Hi-Hat、Open Hi-Hat、Clap、Rimshot 六条轨道；
- 每一步只允许 0 或 1，不支持力度、Swing、三连音和微时序；
- 模型输出 `easyinput.pattern.v1` JSON；
- 实验 Harness 校验 JSON、产品约束并转换为六个 16-bit Mask；
- 固件收到原子 `PATTERN` 命令并返回 ACK 后，记为协议接受和 Pattern 状态应用成功；这不等同于对精确固件镜像及声学播放的可复现实机验收。

本轮只覆盖文字生成 Pattern 和基于既有 Pattern 的局部修改，不覆盖录音识别、Audio-to-MIDI、AI 音色生成、多小节 A/B Pattern 或 AI 对实体 Pad 演奏的风格解释。

## 3. 实验设计

候选包括一个本地小模型和两个云端 Flash 模型：

| 候选 | 部署 | 思考配置 |
| --- | --- | --- |
| `qwen3.5:2b` | 本机 Ollama | 关闭 |
| `glm-5.3-flash` | 云端 API | 低强度开启 |
| `deepseek-v4-flash` | 云端 API | 关闭 |

正式实验包含 3 个模型乘以 6 个任务，共 18 个首次输出。六个任务由 House、Funk、Country 三个基础生成任务和三个对应的局部修改任务组成。每个模型、每个任务只生成一次，不通过重复采样选择最好结果。

实验统一使用同一套 Prompt、输入输出语义合同和任务约束，但保留产品栈的真实差异：Qwen 通过本机 Ollama 运行并使用 `json_schema`，两个云端模型使用 `json_object`；智谱开启低强度思考，Qwen 与 DeepSeek 关闭思考。记录参数为 `temperature=0.6`、`top_p=0.9`、`maxOutputTokens=1024`。

正式计时前，每个模型各执行一次不计分预热。六条正式结果中，合法云端 Pattern 按同一串口协议和同一设备策略验证；Qwen 因 0/6 最终合法而未下发硬件。评测分为四层：

1. 结构与硬件合法性，30 分；
2. 用户指令满足度，30 分；
3. 单人硬件盲听，30 分；
4. 完整合法 Pattern 延迟，10 分。

实验采用硬门槛：至少 5/6 首次 Schema 合法，且一次修复后 6/6 最终合法；未通过校验的 Pattern 不得下发硬件。

| 模型 | 首次 Schema | 最终合法 | PATTERN ACK | 结构 /30 | 指令 /30 | 延迟 /10 | 自动 /70 | 硬门槛 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| DeepSeek V4 Flash | 6/6 | 6/6 | 6/6 | 30 | 30 | 8 | 68 | 通过 |
| GLM-5.3-Flash | 6/6 | 6/6 | 6/6 | 30 | 30 | 3 | 63 | 通过 |
| Qwen 3.5 2B | 6/6 | 0/6 | 未下发 | 20（诊断） | 16.667（诊断） | 0 | 36.667（诊断） | 未通过 |

DeepSeek 与智谱的结构和指令得分相同，自动分的 5 分差距全部来自延迟档位。下表均为六条正式调用的中位数：

| 模型 | 首 Token | 完整响应 | 首次 Schema 合法 | 一次修复响应 | 最终合法 Pattern | 延迟分 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepSeek V4 Flash | 0.7515 秒 | 2.1200 秒 | 2.1205 秒 | 未触发 | 2.1205 秒 | 8 |
| GLM-5.3-Flash | 1.9405 秒 | 7.5075 秒 | 7.5075 秒 | 未触发 | 7.5075 秒 | 3 |
| Qwen 3.5 2B | 0.4600 秒 | 7.3620 秒 | 7.3620 秒 | 6.7515 秒 | 无 | 0 |

DeepSeek 最终合法 Pattern 的中位延迟约为智谱的 28.2%，即本次环境中约快 3.54 倍。Qwen 虽能首次输出 Schema 合法 JSON，但六条在一次修复后仍全部未通过最终约束或编辑策略校验；根据冻结规则，未得到最终合法 Pattern 时延迟强制记 0 分。

Qwen 的结果只说明当前 `qwen3.5:2b` 候选在六个固定任务中未达到 MVP 可靠性门槛，不能外推为所有本地模型都不可用。

## 5. 单人硬件盲听结果

正式 v1 单人 Pilot 使用固定盲序。用户随后报告设备已烧录调整后的音频；由于设备镜像哈希、烧录日志和读回哈希未验证，本文只把它记录为用户报告的音频条件变化。随后使用同一批 12 条云端模型 Pattern 和新匿名顺序完成 blind-v2 后验复测。

### 正式 v1 单人 Pilot

| 模型 | 风格辨识度 /5 | 律动自然度 /5 | 直接使用意愿 /5 | 盲听 /30 | 自动 /70 | 描述性观测总分 /100 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepSeek V4 Flash | 3.667 | 3.500 | 3.333 | 18.750 | 68 | 86.750 |
| GLM-5.3-Flash | 4.167 | 3.500 | 3.500 | 20.417 | 63 | 83.417 |

v1 受到闭镲听感、固定播放顺序和单人量表校准的混杂影响，状态记为 `human_listening_confounded`。评分从页面 DOM 恢复，没有完整的会话时间戳和播放次数记录，因此保留为原始 Pilot，不与 v2 平均。

### blind-v2 后验复测

blind-v2 每条 Pattern 播放一次，没有重听。

| 模型 | 风格辨识度 /5 | 律动自然度 /5 | 直接使用意愿 /5 | 盲听 /30 | 自动 /70 | 描述性观测总分 /100 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepSeek V4 Flash | 4.000 | 4.000 | 3.500 | 21.250 | 68 | 89.250 |
| GLM-5.3-Flash | 4.667 | 4.000 | 3.833 | 23.750 | 63 | 86.750 |

智谱在本轮风格辨识度、直接使用意愿和盲听换算分上更高；律动自然度持平。正式 v1 的描述性总分差为 3.333，已进入不超过 5 分的补测区间；blind-v2 的后验差距仍为 2.5。三个区分性用例的补测未执行，因此这些总分用于记录当前观测，不用于宣称最终 benchmark 冠军。

本次只有一名评价者。完全相同的 E-HOUSE Pattern 在两轮盲听中仍出现 1 至 2 分的单项波动，说明顺序、量表熟悉度和重复测量噪声足以覆盖当前模型听感差距。

## 6. 决策依据

DeepSeek V4 Flash 被选为 MVP 接入方案，依据依次是：

1. 6/6 首次合法、6/6 最终合法，并取得 6/6 `PATTERN` ACK；
2. 结构和指令两项均满分，没有用速度交换协议可靠性；
3. 完整合法 Pattern 的中位延迟为 2.1205 秒，约为智谱的 28.2%，更适合生成后立即预览并应用到硬件的交互；
4. 单人盲听未胜出；本轮将人工听感作为独立观察项，不以主观最高分作为唯一选型标准；
5. 当前本地 2B 候选未通过可靠性硬门槛，暂不承担首版生成链路。

因此，本轮选择的是满足硬门槛后交互效率更高的产品配置，而不是人工听感分最高的模型。

## 7. 已知限制与表述边界

- 智谱使用低强度思考模式，DeepSeek 使用非思考模式。本实验比较的是候选调用配置，不是完全同推理条件下的纯模型能力。
- blind-v2 是单人、每条一次播放的后验复测。实验没有采用能够支持统计显著性或普遍用户偏好判断的多评价者、重复测量设计。
- blind-v2 同时更换六个 PCM、重调六轨增益并改变播放顺序，不能把分数变化归因于闭镲单项。
- `PATTERN` ACK 证明固件接受了命令，但当前设备状态没有返回固件镜像或音色资产哈希，不能据此宣称对板上精确镜像完成了可复现实机验收。
- 预注册规则要求前两名总分差不超过 5 分时补测三个区分性任务。本项目基于 MVP 进度停止补测，因此选型结论是产品决策，不是最终 benchmark 排名。

对外可表述为：DeepSeek V4 Flash 是 EasyInput AI 鼓点 MVP 的选定接入模型。不可表述为 DeepSeek 的音乐品味优于智谱，或 DeepSeek 是统计意义上的最终冠军。

## 8. 接入基线

实现状态（2026-08-30）：仓库已实现 DeepSeek 本地代理、候选生成、服务端及网页双重 `easyinput.pattern.v1` 校验、一次定向修复、显式应用和 `PATTERN` ACK 门控。真实 DeepSeek API 与网页状态已验证；真机同步和播放验收尚未执行，因此不能表述为硬件体验已验收。产品决策、交互状态和验收边界见 `docs/ai-pattern-p0-product-decisions.md`。

首版体验闭环按以下合同实现：

```text
用户中文描述
  -> DeepSeek V4 Flash
  -> easyinput.pattern.v1 JSON
  -> Schema 与产品约束校验
  -> 网页展示候选元数据
  -> 用户点击应用，填入已有六轨 16 步音序器
  -> PATTERN 六个 Mask
  -> 固件 ACK
  -> 用户点击原有开始按钮
  -> 硬件播放
```

模型原始输出不得直接发送给开发板。API 密钥不得进入浏览器代码或提交到仓库；网页将通过本地服务调用模型。硬件播放仍由固件的 I2S 与 96 PPQN 时钟驱动，不依赖模型或网络保持实时连接。
