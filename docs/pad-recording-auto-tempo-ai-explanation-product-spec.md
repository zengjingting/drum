# EasyInput AI 鼓机：实体录制、自动 Tempo、16 步 Pattern 与 AI 解释产品规格

日期：2026-08-31  
状态：产品方案基线已形成，协议实现细节待开发确认；尚未按本规格完成开发和真机验收  
适用阶段：实体 Pad 演奏反向进入 16 步音序器，并由 DeepSeek 解释最新 Pattern  
历史基线：[`pad-recording-ai-explanation-mvp-decisions.md`](pad-recording-ai-explanation-mvp-decisions.md)
记录的 Web 录制、事件上报、固定 BPM量化和 AI解释实现仍作为历史证据；与本规格冲突的未来行为
以本文件为准。

## 1. 产品目标

闭合一条可演示、可解释、可真机验收的核心链路：

```text
S8 / 网页开始录制
→ 清空当前工作 Pattern
→ 用户在实体 Pad 上自由演奏
→ S8 / 网页停止录制
→ 核对原始 Pad 事件
→ 本地自动检测 BPM 候选
→ 按所选 BPM 量化为六轨 16 步 Pattern
→ 同步 BPM 与 Pattern 并收到硬件确认
→ 用户编辑、回放和实时调速
→ DeepSeek 解释当前最新 Pattern revision
```

核心产品价值不是“从音频猜鼓点”，而是把开发板已经知道的 Pad 事件可靠转成可编辑节奏，
再让 AI 对结构化节奏给出有拍点依据的解释。

### 1.1 关键决策记录

| 议题 | 当前决定 | 决策依据 | 证据状态 |
| --- | --- | --- | --- |
| 输入识别方式 | 读取固件上报的 Pad 事件，不录制或分析音频 | 硬件已知按键与音色映射，结构化事件更适合首版闭环 | 旧版 Pad 事件链路已实现；新版状态机待验收 |
| Tempo来源 | 停止录制后由本地确定性算法估计，不调用 LLM或音频模型 | BPM是时序计算问题；模型不应进入量化与实时播放链路 | 产品决定；算法阈值待样本和真机校准 |
| Tempo歧义 | 展示推荐、半速和倍速候选，让用户试听选择 | 单小节事件常无法唯一决定感知速度 | 产品决定；候选排序待测试 |
| 录制起点 | 第一条有效 Pad事件固定为第1步 | 消除点击开始到首次敲击之间的人为等待 | 已定位旧版问题；新版行为待验收 |
| 新录制的数据处理 | 开始录制时清空网页和硬件当前工作 Pattern，保留已保存作品 | 避免旧节奏混入新录制，同时保留用户明确保存的结果 | 用户已确认；待实现新版原子边界 |
| 硬件职责 | S8控制录制；编码器按压 S9控制回放；编码器旋转只在回放中调速 | S8与编码器是独立硬件输入，交互职责必须分离 | 板级引脚事实已核对；项目行为待实现 |
| 音序器入口 | 录制、AI生成和手动编辑复用唯一六轨16步音序器 | 避免两套 Pattern视图和两套下发逻辑 | AI生成链路已复用；录制新版待适配 |
| AI解释对象 | 始终冻结并解释用户点击时的最新 Pattern revision | 用户可能在回放中持续修改，解释必须可追溯且不能覆盖新版本 | 产品决定；revision机制待实现 |
| 设备与 AI状态 | 分开显示设备连接和 AI服务可用性 | USB断开不等于网络/模型不可用，模型错误也不应释放或污染串口状态 | 现有链路已有分层基础；新版联合状态待测试 |
| 网页离线试听 | 首版不增加电脑扬声器播放 | 当前 PCM与实时播放位于硬件侧，浏览器没有等价音色播放链路 | 当前能力边界 |
| BPM与 Pattern提交 | 推荐使用带 revision的原子 `COMMIT` | 防止 BPM、Mask和异步 ACK属于不同版本 | 技术设计建议，不是当前固件已实现能力 |

表中的“产品决定”定义期望体验，不等同于代码已完成；“技术设计建议”允许开发时调整实现方式，
但不得破坏第6节的一致性不变量和第12节的用户验收结果。

## 2. 术语与连接状态

### 2.1 关键术语

- **当前工作 Pattern**：网页音序器当前显示、允许编辑并准备同步硬件的一份六轨 16 步数据。
- **已保存 Pattern**：用户明确点击“保存”后写入浏览器本地的一份作品。清空当前工作 Pattern
  不自动删除它。
- **Pattern revision**：当前工作 Pattern 或 BPM 每发生一次有效变化就递增的本地版本号。
- **已同步 revision**：硬件已经确认 BPM 与 Mask 的最新版本。
- **AI source revision**：某次 AI 解释请求冻结并提交的 Pattern 版本。
- **设备未连接**：USB Web Serial 没有连接开发板。
- **AI 服务不可用**：本地代理、网络或 DeepSeek 不可用。不得笼统写成“离线”。

### 2.2 两条连接轴

| 连接状态 | 手动网页编排 | AI 生成/解释 | 实体录制/硬件播放 |
| --- | --- | --- | --- |
| 设备未连接，AI 服务正常 | 可用 | 可用 | 不可用 |
| 设备已连接，AI 服务不可用 | 可用 | 不可用 | 可用 |
| 两者均正常 | 可用 | 可用 | 可用 |
| 两者均不可用 | 本地编辑与保存可用 | 不可用 | 不可用 |

设备未连接时，网页没有 Web Audio 或电脑扬声器 PCM 播放链路；用户可以编辑、生成、解释和保存，
但不能试听或回放。增加浏览器扬声器预听属于后续独立功能。

## 3. 硬件事实与本项目产品映射

### 3.1 EasyInput V2.0 板级事实

板级事实来自
[`easyinput-board-cy/references/pinout.md`](../easyinput-board-cy/references/pinout.md)：

- S1～S8 是八路独立低有效按键，对应 GPIO `2, 47, 38, 41, 1, 6, 7, 48`；
- S8 是 GPIO48 的普通按键，没有旋转语义；
- 编码器旋转 A/B 是 GPIO17/16 的正交相位输入；
- 编码器自身按压为 S9/GPIO18，是与 S8 独立的低有效按键；
- S1～S8 的业务动作、编码器方向和交互语义由本项目决定，不属于板级默认事实。

### 3.2 本项目冻结的输入职责

| 硬件输入 | 本项目职责 |
| --- | --- |
| S1、S2、S4、S5、S6、S7 | 触发当前六种鼓音色并生成实体 Pad 事件 |
| S3 | 因当前实板硬件异常停用，不进入录制音轨 |
| S8 | 开始/停止实体录制，不触发鼓声 |
| 编码器按压 S9 | 开始/停止当前 Pattern 回放 |
| 编码器旋转 A/B | 仅在 Pattern 正在播放时实时调节 BPM |

录制、BPM 检测和 Pattern 同步期间，编码器按压及旋转均锁定。录制中再次按 S8只执行
“停止录制”，不得触发回放或修改 BPM。

### 3.3 独立工作边界

- 已确认 Pattern 的 I2S 播放、96 PPQN 时钟、LED 和编码器实时调速不依赖网页或 AI；
- S8 录制首版依赖网页连接，因为自动 BPM、16 步量化和 AI 解释在本地网页服务完成；
- 网页未连接或未声明录制就绪时，S8不得清空当前 Pattern或进入无法完成的录制；
- 设备未连接时，编码器按压仍可回放最后一次硬件已确认 Pattern，保证基础独立性。

## 4. 完整用户操作链路

### 4.1 准备

用户连接设备，硬件处于停止状态。页面同时显示：

- 当前硬件 BPM；
- 当前工作 Pattern；
- 设备连接状态与 AI 服务状态；
- 录制、播放、保存和 AI 解释按钮的实际可用性。

如果设备正在播放，用户必须先停止，才能开始录制。

### 4.2 开始录制并清空旧 Pattern

用户按 S8或点击网页“开始录制”。两种入口必须进入同一个固件录制入口，并产生相同的
`record started` 边界。

开始录制的原子行为是：

1. 确认设备已连接、已录制就绪、未播放、未同步；
2. 清空固件当前六轨 Mask；
3. 清空网页当前工作 Pattern；
4. 旧 AI 解释立即失效；
5. 已保存 Pattern 保留，不自动删除；
6. 捕获清空后的 I2S frame 边界并开始逐事件上报；
7. 页面只有收到硬件 `record started` 后才显示“正在录制”。

录制期间：

- 音序器为空且只读，不显示旧 Pattern；
- Tempo 显示 `FREE PLAY / -- BPM`；
- S1～S7即时发声并上报事件，S3仍停用；
- S8变成停止录制；
- 编码器、播放、Tempo、音序格、AI 生成和 AI 解释均锁定；
- 不播放额外节拍器 click。

### 4.3 停止录制与事件完整性核对

用户再次按 S8或点击网页“停止录制”。固件返回停止 frame、最后事件号和累计 dropped 数。
网页按以下顺序核对：

1. 事件号连续；
2. 每个事件来自 `hardware`；
3. track 位于 0～5；
4. frame 位于开始和停止边界内；
5. dropped 在录制期间没有增加。

失败时保持当前工作 Pattern为空，不恢复刚刚清除的旧工作 Pattern，也不修改硬件 BPM。用户可
重新录制或主动恢复上一次已保存 Pattern。

### 4.4 自动 Tempo 检测

事件核对通过后，Tempo 模块进入 `AUTO · 检测中`。检测完全在本地完成，不调用大模型，也不读取
麦克风或扬声器音频。

检测输入：

- 原始 Pad track；
- 每次触发的 I2S frame；
- 48 kHz 项目采样率；
- 40～240 BPM 产品范围；
- 单小节、4/4、16 步合同。

算法输出：

- 推荐 BPM；
- 最多三个半速/正常/倍速候选；
- 每个候选的量化误差、有效事件数和超出首小节数量；
- `stable` 或 `ambiguous` 的定性判断，不展示未经校准的百分比置信度。

最小候选方法：

1. 计算相邻事件和必要的成对事件间隔；
2. 假设间隔对应若干个 1/16 步，生成 40～240 BPM 候选；
3. 以首次 Pad frame 为相位锚点，分别吸附到候选网格；
4. 比较归一化落格误差、首小节覆盖、有效格数量和极端速度惩罚；
5. 合并近似候选，并显式保留常见半速/倍速歧义。

少于 4 次有效敲击，或所有候选都无法形成可用 16 步网格时，不声称识别成功。页面显示
“无法稳定判断速度”，保留空 Pattern，并允许重新录制。若多个候选得分接近，则进入
`ambiguous`：仍展示推荐项及半速/倍速候选，但明确提示用户试听选择，不把推荐项包装成唯一正确答案。

Tempo 模块展示：

```text
TEMPO · AUTO

   40
   BPM

检测完成 · 基于 8 次敲击
[ 40 推荐 ] [ 80 ] [ 160 ]
```

本地计算通常只需毫秒级。页面可以先渲染一次“检测中”再在下一帧展示结果，但不得人为制造
数秒等待。

### 4.5 生成 16 步预览

推荐候选自动选中，并使用同一份不可变原始事件重新量化：

```text
framesPerStep = sampleRate × 60 / selectedBpm / 4
step = round((event.frame - firstPadFrame) / framesPerStep)
```

规则：

- 第一次实体 Pad 固定为第 1 步；
- 同轨同格合并，不同轨可以同格；
- 超出第 16 步的事件不挤入末格，并显示忽略数量；
- 选择其他 BPM 候选时，必须从原始事件重新量化，不能缩放已经量化的 Mask；
- 预览只使用唯一主音序器，不建立第二套录制音序图；
- 默认候选会自动进入同步，不增加“应用”按钮；用户仍需主动开始播放。

### 4.6 同步 BPM 与 Pattern

系统为当前结果创建不可变提交快照：

```json
{
  "revision": 12,
  "bpm": 40,
  "masks": [4369, 0, 0, 0, 21845, 0]
}
```

提交必须满足：

- 硬件保持停止；
- BPM 与六轨 Mask属于同一 revision；
- 同步期间所有硬件输入和相关网页操作锁定；
- 只有硬件确认最新 revision 后，“开始播放”和“AI 解释”才可用；
- 旧 ACK、旧状态和较早异步任务不能覆盖更新 revision。

推荐在本轮固件协议升级中新增一个原子 `COMMIT` 命令，一次携带 revision、BPM和六轨 Mask；
固件在音频任务中一次应用并回传带 revision 的 ACK。若仍沿用分开的 `BPM` 与 `PATTERN`，网页
必须固定快照、串行发送并确认，不能在等待期间继续读取可变全局 `desiredBpm`。

候选切换会创建新 revision。首版可以在一次同步完成前暂时锁定候选，完成后允许再次选择并重新
提交，避免并行 COMMIT。

### 4.7 编辑、保存与回放

同步成功后进入 `ready`：

- 音序器可直接点击编辑；
- 每次编辑创建新 revision并同步 Mask；
- 保存只写入当前浏览器，不负责播放；
- S8开始一轮新录制，并再次清空当前工作 Pattern；
- 编码器按压 S9或网页“开始”启动回放。

回放期间：

- 编码器按压 S9或网页“停止”结束回放；
- 编码器旋转与网页 Tempo 加减解锁，用于实时调节硬件 BPM；
- 硬件回报 BPM作为播放时真实来源，网页数值必须实时跟随；
- 每次硬件确认的 BPM变化也创建新的 Pattern revision并使旧 AI 解释过期；
- S8锁定，避免播放时突然清空并录制；
- 用户可以实时编辑音序格；Mask同步必须串行，不能和 BPM确认共用一个可变目标值；
- 不混入不可见 click，只播放六轨 Pattern。

停止回放后，编码器旋转与网页 Tempo 加减再次锁定，保留最后确认 BPM。

### 4.8 AI 解释最新 Pattern

AI 解释既可以用于实体录制 Pattern，也可以用于网页手动编排或 AI生成后应用的 Pattern。它只接收
结构化快照，不接收录音：

```json
{
  "sourceRevision": 15,
  "source": "hardware_recording",
  "bpm": 43,
  "tracks": "六轨 16 步数据",
  "approximateQuantization": true
}
```

AI只负责：

- 风格倾向和定性置信度；
- 引用具体音轨和步数的判断依据；
- 节奏结构说明；
- 一条可执行修改建议；
- 单小节输入的判断边界。

AI不负责 Pad 识别、BPM 数值计算、16 步量化、Pattern同步或硬件播放。

点击“AI 解释”始终读取当前最新 Pattern revision。设备在线时，按钮应等到该 revision 收到硬件
确认，确保用户看到、听到和解释的是同一版本；设备未连接时，可以解释最新网页草稿，但显示
“尚未同步硬件”。

AI请求与硬件播放相互独立：

- AI思考时仍允许用户停止播放；
- 请求绑定 `sourceRevision` 和独立 `requestId`；
- 如果用户在请求期间编辑音序格或调整 BPM，返回结果立即标记为旧版本；
- 页面显示“本解释对应 v15，当前 Pattern 已更新至 v17”；
- 下一次点击改为“解释最新版本 v17”；
- 较早请求晚返回时不得覆盖较新解释；必要时取消旧请求或丢弃旧结果；
- DeepSeek失败不影响 Pattern、硬件播放或保存。

本阶段不保存完整 Pattern版本历史；revision只用于一致性、过期提示和拒绝旧异步结果。

## 5. 联合状态机

### 5.1 主流程

```text
idle / ready
  ↓ S8 或网页开始录制
clearingPattern
  ↓ 固件清空并确认录制边界
recording
  ↓ S8 或网页停止录制
stopping
  ↓ 事件完整性通过
detectingTempo
  ↓ 产生候选并选择推荐
previewing
  ↓ 固定 revision + BPM + masks
syncing
  ↓ COMMIT ACK
ready
  ↓ 编码器按压 S9 / 网页开始
playing
  ↓ 编码器按压 S9 / 网页停止
ready
```

任意失败进入 `error`，但错误必须附带来源：设备连接、录制事件、Tempo检测、协议同步或 AI 服务。

### 5.2 子状态与来源

| 子系统 | 状态 | 权威来源 |
| --- | --- | --- |
| Capture | `idle/clearing/starting/recording/stopping/processing/error` | 固件边界与连续事件号 |
| Tempo | `manual/free/detecting/candidates/selected/syncing/confirmed/live/error` | 停止时网页候选；播放时硬件 STATE |
| Pattern | `empty/preview/dirty/syncing/synced/error` | 网页当前 revision；ACK 后硬件确认 |
| Transport | `stopped/starting/playing/stopping/error` | 硬件 STATE，不凭按钮点击猜测 |
| AI | `idle/explaining/ready/stale/error` | 绑定 sourceRevision 的后端响应 |
| Device | `disconnected/connecting/online/error` | Web Serial 生命周期 |
| AI Service | `ready/requesting/unavailable/error` | 本地代理健康与请求结果 |

### 5.3 硬件与网页控制矩阵

| 主状态 | S8 | 编码器按压 S9 | 编码器旋转 | 网页录制 | 网页播放 | Tempo ± | 音序格 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `ready` | 开始录制 | 开始播放 | 锁定 | 可用 | 可用 | 锁定 | 可编辑 |
| `clearing/recording/stopping` | 录制中仅可停止 | 锁定 | 锁定 | 录制中仅可停止 | 锁定 | 锁定 | 空白只读 |
| `detecting/previewing/syncing` | 锁定 | 锁定 | 锁定 | 锁定 | 锁定 | 锁定 | 预览只读 |
| `playing` | 锁定 | 停止播放 | 实时调速 | 锁定 | 停止可用 | 可用 | 可编辑，串行同步 |
| `error` | 依错误来源 | 仅在硬件可安全停止时可用 | 锁定 | 重试 | 不得播放未确认 revision | 锁定 | 保留当前可诊断状态 |

Tempo候选芯片不是 Tempo ±。候选在检测完成且硬件停止时可选；Tempo ±只在播放中用于实时微调。

## 6. Pattern revision 与一致性合同

网页不再用一个可变 `desiredBpm` 同时代表候选、硬件状态和同步目标。至少拆分为：

- `deviceBpm`：硬件当前确认 BPM；
- `detectedBpm`：本次录制推荐候选；
- `selectedBpm`：用户当前选中的候选或网页草稿值；
- `commitBpm`：某一次不可变同步快照中的 BPM；
- `currentRevision`：网页当前 Pattern版本；
- `syncedRevision`：硬件已经确认的最新版本。

不变量：

1. 量化只读取不可变事件快照和 `selectedBpm`；
2. 同步只读取不可变 `{revision, bpm, masks}`；
3. 播放只能使用 `syncedRevision`；
4. AI解释默认只读取最新 `currentRevision`；
5. 在线时 AI解释按钮等待 `currentRevision === syncedRevision`；
6. 硬件 STATE不能在录制或检测中静默覆盖网页候选；
7. 旧 ACK、旧模型响应和旧检测任务均通过 revision/requestId拒绝。

## 7. 固件与协议设计要求

### 7.1 固件内部职责

- 在板级声明中增加 S8/GPIO48，不把它放入鼓声音轨数组；
- S8使用独立消抖并调用统一 Capture Controller；
- 网页 `RECORD START/STOP` 与实体 S8调用同一状态转换；
- 录制状态从 USB 模块局部变量提升为固件共享产品状态；USB只负责传输，不作为状态权威；
- 编码器输入根据产品状态决定是否接受按压或旋转；
- Pattern播放关闭 audible click，但保留 I2S、96 PPQN、音序器和 LED 时钟；
- 任意状态转换继续保持实体 Pad即时发声和事件完整性。

### 7.2 建议协议扩展

握手建议升级协议版本并声明：

```json
{
  "protocolVersion": 3,
  "capabilities": [
    "pattern",
    "trigger",
    "sequencer",
    "padEvents",
    "hardwareCaptureButton",
    "revisionCommit"
  ]
}
```

录制边界增加来源和固件模式：

```json
{
  "type": "record",
  "phase": "started",
  "origin": "s8",
  "frame": 519465664,
  "lastEvent": 77,
  "dropped": 0
}
```

推荐原子提交：

```text
COMMIT 12 40 4369 0 0 0 21845 0
```

成功响应：

```json
{
  "type": "ack",
  "command": "COMMIT",
  "revision": 12,
  "bpm": 40,
  "pattern": [4369, 0, 0, 0, 21845, 0]
}
```

固件必须拒绝在 `recording` 或不安全播放状态执行 COMMIT。旧协议仍可保留手动兼容，但网页只有
看到新 capability 才启用 S8录制与自动 Tempo完整闭环。

### 7.3 连接异常的解锁

如果 S8录制依赖网页处理，固件不得在网页断开后永久停留 `processing`。首版要求：

- 网页在录制前完成 capability握手并声明 capture ready；
- 串口断开、事务超时或网页明确 ABORT 时，固件保持空 Pattern并回到安全 `ready`；
- 超时不得恢复刚刚清除的旧工作 Pattern；
- 状态变化必须通过 STATE或错误消息可诊断。

具体超时时长由实现和真机测试确定，不在产品文档中虚构为已验证硬件参数。

## 8. 前端详细设计

### 8.1 Tempo模块

| Tempo状态 | 主数字 | 辅助文案 | 可用操作 |
| --- | --- | --- | --- |
| 默认停止 | 当前 BPM | `MANUAL` 或来源 | 无 |
| 录制中 | `--` | `FREE PLAY · 已记录 N 次敲击` | 无 |
| 检测中 | `--` | `AUTO · 正在检测速度…` | 无 |
| 候选完成 | 推荐 BPM | `AUTO · 基于 N 次敲击` | 候选芯片 |
| 同步中 | 所选 BPM | `正在同步 Pattern vN…` | 无 |
| 回放中 | 硬件 BPM | `LIVE` | ±与编码器 |
| 检测失败 | 保持 `--` | `无法稳定判断速度` | 重新录制 |

### 8.2 音序器

- 开始录制立即清空当前工作 Pattern；
- 录制中为空白只读；
- 检测完成后一次显示推荐候选预览；
- 同步中只读并显示 revision；
- ACK后可编辑；
- 播放时显示硬件 sequenceStep，不给 click建立虚假亮格；
- 修改创建 revision并使旧 AI解释过期。

### 8.3 AI解释区

- 显示 Pattern来源、revision、BPM和硬件同步状态；
- 请求中显示真实步骤：“读取六轨数据 → 提取结构 → 请求 AI解释”；不得写“读取音频”；
- 结果显示 `本解释对应 vN`；
- 当前版本变化后显示明显的过期提示；
- CTA改为“解释最新版本 vN”；
- AI服务错误不改变设备连接状态。

## 9. 失败处理与数据保留

| 失败点 | 当前工作 Pattern | 已保存 Pattern | 硬件 | 用户反馈 |
| --- | --- | --- | --- | --- |
| 清空/开始边界失败 | 以硬件确认状态为准 | 保留 | 停止 | 无法开始录制 |
| 空录制 | 保持空 | 保留 | 空 Pattern | 未收到有效敲击 |
| 事件编号跳变或 dropped增加 | 保持空 | 保留 | 空 Pattern | 事件丢失，请重录 |
| 有效事件过少或没有可用 Tempo候选 | 保持空 | 保留 | 空 Pattern | 无法判断速度，请重录 |
| COMMIT失败 | 保留网页预览但标记未同步 | 保留 | 禁止播放新 revision | 同步失败，可重试 |
| 串口断开 | 保留网页草稿 | 保留 | 保持最后已确认安全状态 | 设备未连接 |
| AI失败 | Pattern不变 | 保留 | 播放不受影响 | AI服务错误 |
| AI返回旧 revision | Pattern不变 | 保留 | 不受影响 | 解释已过期，不覆盖新结果 |

## 10. 明确不做

- 麦克风录音、音频上传、Audio-to-MIDI或音频理解模型；
- 使用 LLM计算 BPM或负责量化；
- 力度、Swing、微时序和人性化偏移保真；
- 多小节、Pattern A/B、撤销栈和完整版本历史；
- 电脑扬声器 Web Audio预听；
- AI自动修改或自动播放 Pattern；
- 未经用户播放确认就声称节奏识别准确；
- 把单小节 Pattern解释包装成完整音乐流派识别。

## 11. 开发顺序

- 用本文件替代旧固定 BPM和旧状态机的未来实现合同；
- 为联合状态、控制矩阵、revision拒绝旧结果和失败分层写测试；
- 保留现有 Trace，新增 S8来源、Tempo候选与 revision字段。

### P0-1：固件模式与输入职责

- 增加 S8/GPIO48；
- 分离 S8录制、编码器按压播放、编码器旋转调速；
- 录制/处理/同步期间锁定编码器；
- 关闭 audible click；
- 将 Capture状态从 USB局部变量提升为共享状态；
- 扩展协议并完成 host测试。

### P0-2：本地 Tempo检测与前端状态机

- 实现纯函数候选生成、评分、半/倍速去重和失败阈值；
- Tempo模块增加 free/detecting/candidates/syncing/live；
- 主音序器实现清空、预览、候选重算和只读边界；
- 拆分 device/detected/selected/commit BPM。

### P0-3：revision提交与硬件闭环

- 实现不可变 COMMIT快照和 ACK revision；
- 只允许已同步 revision播放和在线 AI解释；
- 验证候选切换、快速编辑、实时调速与断线恢复。

### P0-4：AI解释最新版本

- 修改后标记旧解释过期；

### P0-5：真机验收与文档回填

- 构建、烧录并确认 GPIO、协议版本和输入模式；
- 做固定节奏、半/倍速歧义、快速连击、断线和 AI延迟场景；
- 将自动化通过、固件烧录、串口证据和用户听感分层记录。

## 12. 验收标准

1. S8/GPIO48和编码器 S9/GPIO18被识别为独立输入，职责不串线。
2. S8和网页按钮均能开始/停止同一录制事务，并产生可识别 origin。
3. 开始录制后网页与硬件旧工作 Pattern均清空，已保存 Pattern不被删除。
4. 录制期间只有 S8停止有效；编码器按压、旋转、网页 Tempo和回放均锁定。
5. Pad事件号连续、track正确、dropped不增加；异常时不生成看似完整的 Pattern。
6. 规则演奏能够得到合理推荐 BPM及半/倍速候选；不稳定输入明确失败而非伪造高置信度。
7. 切换 BPM候选会从原始事件重新量化，并在唯一主音序器中更新。
8. BPM与六轨 Mask以同一 revision得到硬件确认；旧 ACK不能覆盖新版本。
9. 点击播放后只听到音序器六轨声音，不再出现没有对应格的 click。
10. 编码器仅在回放时实时调 BPM，网页 Tempo跟随硬件变化。
11. 回放中修改多个版本后，下一次 AI解释只读取最新已确认 Pattern。
12. AI请求期间继续播放或编辑不会卡住硬件；旧解释明确过期且旧响应不覆盖新结果。
13. 设备未连接时仍可网页编排、AI生成/解释和保存，但不能误导用户能够通过电脑扬声器播放。
14. AI服务失败不改变设备在线状态，不影响硬件播放和本地编辑。
15. 网页断开后硬件继续播放最后一次已确认 Pattern；录制处理中断不会永久锁死输入。

## 13. 对外表述边界

完成本规格并通过真机验收后，可以表述为：

> 将实体 Pad演奏事件转换为可编辑的六轨16步节奏，使用本地 Tempo候选算法处理自由演奏速度，
> 并由 LLM基于最新符号化 Pattern给出带拍点证据的风格解释；实时播放、调速和灯效继续由板端
> I2S与96 PPQN时钟驱动。

不得表述为“AI听懂录音”“精准转录任意鼓演奏”“完成通用 BPM识别 benchmark”或“完成完整音乐
流派识别”。自动化测试、协议 ACK、烧录成功和用户真实听感仍是不同证据层。
