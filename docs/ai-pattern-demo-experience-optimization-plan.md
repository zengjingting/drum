# EasyInput AI 鼓机：演示体验优化方案

日期：2026-08-31

状态：方案已实施并完成自动化、真实模型与浏览器验收；真机操作体验待用户复验

适用范围：在已验收的“实体 Pad 演奏 → 自动 Tempo → 六轨 16 步 Pattern → AI 解释”基础上，
优化演示视频中的信息层级、反馈可见性和初学者学习体验。本轮不修改固件、串口协议、音色、量化算法
或模型选型。

## 1. 产品目标

本轮不是单纯美化页面，而是让第一次看到产品的人在 30 秒内理解：

1. 硬件演奏已经被系统读取并量化；
2. AI 正在分析当前 Pattern，而不是处理实时音频；
3. AI 能告诉初学者“这更像什么风格、这种风格是什么、为什么像、如何继续改”；
4. AI 请求不会阻断硬件播放和 Pattern 编辑。

对秋招 AI 硬件产品经理项目展示的价值排序为：闭环是否容易讲清楚、AI 与确定性硬件链路边界是否
可信、用户反馈是否明确、视觉是否达到可演示完成度。

## 2. 实现优先级

### P0：录制演示视频前完成

| 优化项 | 产品价值 | 实施内容 |
| --- | --- | --- |
| AI 生成中状态 | 证明 Pattern 已进入 AI 分析链路 | 高亮状态、旋转指示、动态等待秒数、阻止重复请求 |
| AI 完成与失败状态 | 给出明确结果并体现系统边界 | 完成显示秒级耗时；失败提示 Pattern 和播放不受影响并允许重试 |
| 风格简介 | 回答初学者看到陌生流派后的第一问题 | 在风格名下增加起源、文化背景和常见歌曲场景 |
| 答案可读性 | 让视频中解释内容真正可读 | 独立滚动回复区、正文层级和首屏示例 |
| 自动 Tempo 简化 | 缩短录制后的决策路径 | 自动采用推荐 BPM，隐藏候选按钮，保留内部候选诊断数据 |
| 主界面去噪 | 让核心闭环成为视觉中心 | 删除板级迁移、工程编号、模型 Ready、每小节时长等信息 |

### P1：P0 稳定后完成

| 优化项 | 产品价值 | 实施内容 |
| --- | --- | --- |
| 标题栏对齐 | 提升整体完成度 | 品牌、Tempo、播放器和连接状态垂直居中 |
| 播放器视觉 | 强化实时硬件节拍感 | 圆形播放/停止图标和四个节拍圆点 |

P1 不得以牺牲 P0 稳定性或 16 步格子正方形为代价。

## 3. 自动 Tempo 产品决策

录制停止后继续运行现有确定性 Tempo 检测，但主界面不再要求用户在多个候选中试听选择：

```text
录制停止
→ Tempo 显示“检测中”
→ 本地算法生成候选并选出 recommendedBpm
→ 直接以 recommendedBpm 重新量化
→ 同 revision 同步 BPM + Pattern
→ Tempo 显示“检测完成 · 53 BPM”
```

边界：

- `tempoDetection.candidates` 继续保留在内存和诊断埋点中，便于排查倍速/半速歧义；
- 不渲染候选按钮，也不进入“等待用户选择”状态；
- 回放阶段仍允许通过编码器或网页加减按钮调整 BPM；
- 本轮不改变 Tempo 检测算法和推荐规则，不新增 AI Tempo 检测。

## 4. AI 解释合同升级

已验收的 `easyinput.pattern.explanation.v2` 保留为历史合同。新增必填风格简介属于破坏性字段变更，
因此目标合同升级为 `easyinput.pattern.explanation.v3`，不原地覆盖 v2。

### 4.1 模型输出 Schema（带字段注释）

以下为 JSONC 示例；正式模型响应必须是不含注释的标准 JSON：

```jsonc
{
  "schemaVersion": "easyinput.pattern.explanation.v3", // 输出合同版本，防止旧版响应被新网页误用
  "closestStyle": "Trap", // 当前单小节 Pattern 最接近的一种风格名称，不代表完整歌曲的确定流派
  "styleOverview": "Trap 起源于美国南部嘻哈文化，常见于说唱、Hip-Hop 以及强调低频氛围的流行音乐。", // 1–2句风格起源、文化背景和常见使用场景；不得讲鼓点编排技巧
  "reasons": [ // 只解释当前 Pattern 实际存在的风格依据
    {
      "track": "closed_hat", // 支撑判断的板载音轨，只能取六条固定轨道之一
      "steps": [1, 3, 5, 7], // 对应音轨中真实为1的1-based步数
      "reason": "闭镲连续细分让节奏具有更紧凑的推进感。" // 面向初学者的判断原因
    }
  ],
  "styleLesson": { // 与当前 Pattern 事实分开的风格编排知识卡片
    "title": "Trap 鼓点通常怎么编排？", // 风格小课堂标题
    "content": "Trap 常通过细密闭镲、错落底鼓和明确反拍形成张力。闭镲变化负责推动感，底鼓与拍手声共同塑造重心。" // 2–4句常见鼓组分工、典型落点和律动特点
  },
  "improvementSuggestions": [ // 当前六轨16步开关音序器可执行的1–2条建议
    {
      "suggestion": "在第15步增加一次闭镲。", // 用户可以在当前 Pattern 上尝试的具体修改
      "expectedEffect": "小节结尾会更有向下一小节推进的感觉。", // 修改后可能出现的听感变化
      "learningPoint": "练习使用小节末尾的细分变化制造推动感。" // 这次修改对应的编排学习目标
    }
  ]
}
```

### 4.2 字段边界

| 字段 | 校验与展示要求 |
| --- | --- |
| `schemaVersion` | 必须为 `easyinput.pattern.explanation.v3` |
| `closestStyle` | 1–40字符；UI 前置“最接近的风格” |
| `styleOverview` | 1–300字符、含简体中文；只谈起源与使用场景 |
| `reasons` | 1–6条；音轨和步数必须引用真实亮格 |
| `styleLesson` | 标题1–80字符；正文1–400字符、2–4句为提示词要求 |
| `improvementSuggestions` | 1–2条；三项文本均为1–240字符且含简体中文 |

后端和网页继续做双重结构校验。语义上是否严格区分 `styleOverview` 与 `styleLesson` 由提示词、
固定用例和人工验收共同保证，不包装成 JSON Schema 已经完全解决。

## 5. AI 状态设计

AI 解释状态只作用于 Copilot，不改变播放、连接和 Pattern 编辑状态。

| 状态 | 用户可见反馈 | 行为 |
| --- | --- | --- |
| `idle` | 非空 Pattern 时显示“AI 解释” | 可以发起请求 |
| `loading` | 旋转指示 + “AI 正在分析你的鼓点… 已等待 X.X 秒” | 禁止重复请求；硬件继续播放 |
| `success` | “AI 解释完成，用时 X.X 秒” | 渲染 v3；允许继续编辑或重新解释 |
| `stale` | “Pattern 已更新，这份解释对应修改前版本” | 保留旧解释但明确过期 |
| `error` | “AI 解释失败，Pattern 和硬件播放不受影响 · 重新解释” | 不清空 Pattern、不改串口状态 |

模型返回的毫秒耗时只用于内部合同；前端统一换算为秒并保留一位小数，例如
`7197 ms → 7.2 秒`。Pattern revision 移到音序器区域显示，不再放入完成文案。

## 6. 页面信息架构与布局

### 6.1 桌面布局

- 页面主体采用约 `61% / 39%` 的音序器/Copilot比例，让16步编排保持主视觉；
- 音序器轨道名列设置固定宽度和 `white-space: nowrap`；
- 16步按钮使用 `aspect-ratio: 1`，在可用空间内保持正方形；
- Copilot回复区独立纵向滚动，不能推动整个网页滚动；
- Copilot初始化展示一条 Boom Bap 示例解释，避免未请求AI时出现大面积空白；
- 中小屏继续允许纵向布局，不为桌面单屏目标压缩到不可读。

### 6.2 功能归属

- 顶部硬件栏：Tempo、播放、圆形录制、保存、四拍圆点、Hardware Pad Monitor和连接状态；
- 左侧音序器：只负责展示和编辑当前六轨16步 Pattern；
- 右侧AI Copilot：同时承载“AI编写鼓点”和“AI解释当前 Pattern”；
- “生成鼓点”“应用”“AI解释”同排展示，但生成后仍必须明确点击“应用”才改写当前 Pattern；
- Pattern播放时，四拍圆点、音序播放头和Hardware Pad Monitor按当前步同步高亮；
- 录制状态与AI解释状态使用不同DOM和状态通道，避免两条异步链路互相覆盖文案。

### 6.3 AI 解释展示顺序

```text
最接近的风格
Trap
风格简介

为什么这样判断
风格小课堂
让鼓点更好听，可以试试
```

### 6.3 从主界面删除或降级的信息

| 当前信息 | 处理方式 |
| --- | --- |
| `S3 暂停使用 · Closed Hi-Hat 已迁移至 S7` | 删除；硬件映射直接以 S7 标签表达 |
| `实体演奏 · 自动 Tempo… · 超出首小节…` | 主界面改为“录制完成 · 53 BPM”；详细计数仅保留埋点 |
| `X.XX 秒 / 小节` | 删除 |
| `DEEPSEEK V4 · READY` | 删除 |
| `01 / PATTERN` 等工程编号 | 删除 |
| “网页会再次校验六轨16步结构” | 删除 |
| Pattern 名称输入框 | 删除；保存时内部使用默认名称“我的鼓点” |

## 7. 播放器视觉

- 播放按钮改为圆形，停止时显示三角播放图标，播放时显示方形停止图标；
- 录制按钮使用独立圆形录音图标，录制中切换为方形停止图标；
- 保留按钮文字的无障碍名称和 `aria-pressed`，视觉上不显示“开始/停止”文字；
- 四拍数字改成四个圆点，并放在Hardware Pad Monitor右上角；
- 当前拍点使用高亮填充和轻微光晕；
- 尊重 `prefers-reduced-motion`，关闭不必要动画。

## 8. 实施顺序

1. 新增 v3 Schema、后端提示词、Mock、强校验和测试；
2. 更新网页 v3 校验与 `styleOverview` 渲染；
3. 将 Tempo 流程改为推荐值自动提交，删除候选按钮；
4. 实现 AI loading/success/error/stale 状态和秒级耗时；
5. 调整布局、字号、轨道名与正方形步进格；
6. 删除主界面冗余信息和 Pattern 名称输入框；
7. 重做播放器图标与四拍圆点；
8. 运行 Web、主机协议和浏览器回归；最后由用户真机验收。

## 9. 验收标准

1. 录制停止后不再出现 Tempo 候选按钮，推荐 BPM 自动量化并同步；
2. AI 请求中有醒目的进行中指示和递增等待秒数；
3. 完成文案只显示秒级耗时，不混入 Pattern revision；
4. 陌生风格名下有1–2句起源与常见使用场景简介；
5. `styleOverview` 不重复风格小课堂的鼓点编排内容；
6. 原因引用的音轨和步数都能在当前音序器中找到；
7. AI 失败、等待或旧响应不影响硬件播放、连接和 Pattern 编辑；
8. 桌面端 AI 正文清晰可读，16步格子保持正方形，音色名称不换行；
9. 已列出的工程和诊断文案不再占据主界面；
10. 播放/停止与四拍圆点能清楚表达当前实时状态；
11. 自动化、Mock 浏览器、真实 DeepSeek smoke 和用户真机体验分别记录，不相互替代。
12. 圆形录制按钮、保存和 Pad Monitor 位于顶部硬件栏；AI编写与解释位于Copilot，且两类状态互不覆盖。

## 10. 简历表述边界

完成代码和人工验收后，可表述为：

> 面向鼓点编排初学者，设计并落地实体 Pad 演奏量化、自动 Tempo、可编辑16步 Pattern 与
> LLM 风格教学闭环；通过结构化 Schema、真实落点校验、revision 隔离和异步状态反馈，保证
> AI 分析不进入硬件实时音频链路，并持续优化演示可理解性与容错体验。

不得仅凭视觉改版表述为“提升学习效果”或“提高识别准确率”；这两类结果需要后续用户测试数据。
