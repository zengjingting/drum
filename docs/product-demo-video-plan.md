# EasyInput AI Drum Machine 产品演示视频方案

更新日期：2026-08-31  
目标受众：AI 硬件产品经理岗位的招聘方、业务面试官和作品集访客  
主版本：16:9、约 60–65 秒、有设备原声、静音观看也能理解  

## 1. 一句话目标

用一分钟证明：用户既可以用自然语言生成鼓点，也可以直接在实体 Pad 上演奏；两种输入都会进入同一个可编辑的六轨 16 步 Pattern，经过用户确认后由开发板本地播放，并可由 AI 解释风格与编排逻辑。

视频不按页面模块逐项介绍，而按一次完整创作任务展开：

> 描述想法 → AI 生成 → 用户应用 → 真机播放 → 实体演奏 → 自动量化 → AI 解释。

## 2. 证据简报

### 2.1 必须让观众看懂的五个证明点

1. **AI 不是只输出文字**：中文描述会被转换为受硬件约束的六轨 16 步 Pattern。
2. **用户保留控制权**：生成完成后必须点击“应用”，再由独立的播放按钮启动硬件。
3. **软硬件共用同一份状态**：音序器落点、播放推进、Pad Monitor、BPM 与开发板声音/灯光能够对应。
4. **实体演奏可以结构化**：S8 或网页开始录制后，Pad 事件会自动估算 Tempo，并近似量化为可编辑 Pattern。
5. **AI 是学习助手**：AI 解释当前 Pattern 最接近的风格、判断依据、风格知识和可执行的改进建议；实时音频仍在硬件本地运行。

### 2.2 能力与证据状态

| 能力 | 视频中的证据 | 当前口径 |
| --- | --- | --- |
| 中文描述生成六轨 16 步 Pattern | 真实页面输入、生成状态、真实结果 | 已实现；拍摄前需用当前提交复测一次真实 API |
| 生成与应用分离 | 生成后音序器不变，点击“应用”后才填入 | 已实现，可直接实录 |
| Pattern 同步并由硬件播放 | 点击播放、音序器游标、设备声音与灯效 | 必须使用真机实录，不可用 UI 动画替代 |
| 实体 Pad 录制和自动 Tempo | 按 S8、演奏、停止、Tempo 与落格结果 | 已有真机验收记录；需用当前 UI 再录一条连续证据 |
| AI 解释当前 Pattern | 真实解释结果引用当前音轨与步数 | 已实现；不得表述为“AI 读取音频” |
| 网页关闭后硬件继续播放 | 关闭网页，开发板声音与灯效继续 | 固件能力已实现；只有拍摄前现场复测通过才进入成片 |

### 2.3 不在视频中做出的声明

- 不说“AI 听懂了演奏音频”。系统读取的是实体 Pad 事件和量化后的符号化 Pattern。
- 不说“精准转录”。首版是单小节、六轨、16 步、无力度、无 Swing 的近似量化。
- 不把协议 ACK、自动测试或烧录成功包装成用户听感验收。
- 不展示 API Key、串口路径、终端、个人通知或系统设备列表。
- 不使用静态示例回答冒充本次模型真实输出。

## 4. 建议完整旁白

> 这是 EasyInput AI Drum Machine，一个把自然语言、实体演奏和硬件鼓机连成闭环的创作工具。输入想要的风格后，AI 会生成符合六种板载音色和 16 步约束的鼓点；只有点击应用，结果才进入音序器。点击播放后，节拍、声音和灯光都由开发板本地驱动。我也可以按下 S8 直接演奏，系统根据 Pad 事件自动估算速度，并近似量化为可编辑的 Pattern。AI 再基于当前 Pattern 解释最接近的风格、判断依据和改进建议。网页和模型不进入实时音频链路，最后确认的节奏留在硬件上运行。

建议旁白与字幕不要逐字重复：旁白解释逻辑，字幕只保留每段的结果词。

### 5.1 实体演奏内容

优先使用已经在真机上稳定识别、并由用户确认推荐 Tempo 符合听感的那一条演奏，不为了视频强行制造固定数字。若要重新排练，可使用容易看懂的一小节骨架：

- Kick：第 1、9 步；
- Snare：第 5、13 步；
- Closed Hi-Hat：第 1、3、5、7、9、11、13、15 步。

实际录制必须以真机结果为准。若自动 Tempo 得到不同但合理的 BPM，保留真实结果，不在后期改数字。

### 5.2 拍摄规范

- 横屏 16:9，至少 1080p/30 fps；手机后置主摄，固定机位。
- 使用深色、简洁背景；开发板占画面约 50%–65%，手从画面下方进入。
- 锁定曝光和对焦，避免 LED 亮起时画面反复变亮或对焦漂移。
- 保留设备原声；不要加环境音乐盖住 Kick、Snare、Hi-Hat 的差异。
- 若屏幕录制和手机素材分开，在每条开头连续敲三次 S1 作为同步点，剪辑时删除。
- 同一动作至少拍两遍：一遍完整流程，一遍硬件近景。
- 开启勿扰模式，隐藏桌面通知、用户名、串口设备列表和任何密钥。

## 6. 屏幕录制清单

1. 使用正式页面和当前 Git 提交，不使用旧 demo 页。
2. 录制前先连接设备；系统串口选择弹窗不进入成片。
3. 浏览器只保留产品标签页，窗口固定为 16:9；鼠标动作慢而明确。
4. 生成时录到真实加载状态与真实结果。等待过长可以跳切，但不得伪造响应内容或用时。
5. “应用”前停顿，证明音序器尚未被覆盖；“应用”后再停顿，证明唯一主音序器被写入。
6. 播放段至少保留完整四拍，确保游标、四拍圆点和真机声音可核对。
7. AI 解释只展示真实返回；优先截取最接近风格、两条落点依据和一条改进建议。

## 7. 剪辑与视觉规则

- 成片以真实产品 UI 为主，不另外制作一套概念界面。
- 真机动作使用画中画或左右分屏；不要靠旁白声称同步，必须让声音、LED 或 Pad Monitor 至少出现一种可见对应。
- 章节字幕每条控制在 12–16 个汉字，位置固定，避免遮挡音序器和 AI 结果。
- AI 等待、串口选择和无信息操作可以压缩；真实硬件反馈不可加速到无法判断延迟。
- 不用夸张转场。以硬切、轻微缩放和一次高亮框为主，保持产品演示可信度。
- 保留板载鼓声为主音轨；旁白出现时将鼓声音量降低约 4–6 dB，不完全静音。
- 输出一版 60–65 秒完整视频；素材稳定后可再裁一版 18–22 秒无旁白循环版用于作品集首屏。
